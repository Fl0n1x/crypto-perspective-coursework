# Курсова робота: прогнозування відносної тижневої динаміки цін криптовалют

Пашко Назарій, СА-32, МЕТОДИ ТА ЗАСОБИ ПРИКЛАДНОЇ СТАТИСТИКИ, Львів-2026.

## Задача

Для монети, що торгується на Binance, спрогнозувати на момент закриття
тижня, чи буде її дохідність за наступні сім днів вищою за дохідність
медіанної монети того самого тижня. Бінарна класифікація, одиниця
спостереження - монета в конкретному тижні.

## Чому ціль визначена відносно медіанної монети, а не відносно BTC

Дохідність монети складається зі спільного руху всього ринку та власного
відхилення монети від нього. Перша складова однакова для всіх монет тижня
й з ознак окремої монети не виводиться. Якщо ціллю зробити «випередити
біткоїн», у тижні падіння альткоїнів майже всі мітки будуть нульовими, а
в тижні зростання - майже всі одиничними, тож модель вчитиметься вгадувати
ринок замість порівнювати монети. Порівняння з медіанною монетою того
самого тижня цю спільну компоненту усуває: класи стають збалансованими
(49,9 % у train) незалежно від фази ринку.

## Дані

Сира панель «монета - тиждень»: 65 820 записів, 384 монети, 298 тижневих
точок з 3 січня 2021 по 13 вересня 2026 року, 19 числових і 2 категоріальні
ознаки. Джерела (дані отримано 26 вересня 2026 року):

- **Binance Spot API** - повна денна історія OHLCV для пар до USDT;
- **CoinGecko API** - довідник монет, капіталізація та секторні категорії.

Усі ознаки рахуються каузальними ковзними вікнами: значення на момент
прогнозу використовує лише дані до цього моменту. Горизонт цілі дорівнює
тижню, тому періоди сусідніх спостережень не перекриваються.

Структурне очищення вилучило 427 записів: 157 записів, у вікні ознак або
цілі яких торги монети зупинялись на три дні й більше (редомінації QUICK і
SUN, заміна токена STRAX, пауза CVC), і всі 270 записів LUNAUSDT, бо після
краху Terra під тим самим тікером торгувався інший актив (стрибок ціни в
177 400 разів). Після очищення лишилось 65 393 записи й 383 монети.

## Результати

| Етап | ROC-AUC |
| --- | --- |
| Наївний класифікатор | 0,5000 |
| Базовий конвеєр, крос-валідація | 0,5395 |
| Фінальний конвеєр, крос-валідація | 0,5547 |
| Базовий конвеєр, тест (довідково) | 0,5349 |
| Фінальний конвеєр, тест | 0,5503 |

Фінальний конвеєр кращий за базовий у кожному з п'яти фолдів покрокової
крос-валідації, а результат тесту лежить у межах розкиду крос-валідації,
тобто конвеєр не переоцінений. Практична перевірка на 36 тижнях тестового
періоду: відібрані моделлю 20 % монет давали в середньому 0,09 % за тиждень
проти мінус 1,89 % у медіанної монети ринку.

Для порівняння, той самий конвеєр, оцінений на даних навчання, дає
ROC-AUC 0,7608. Різниця показує, наскільки некоректний протокол перевірки
завищує результат.

```
├── Пашко_курсова_робота.docx       текст роботи (64 сторінки)
├── Пашко_coursework.ipynb          повний код (40 кодових комірок)
├── figures/                        виводи комірок для тексту
├── results/key_numbers.json        ключові числа, які цитує текст
├── tools/
│   ├── make_notebook.py            генерує notebook

│   ├── docx/build.py               збирає текст роботи
│   ├── docx/toc.py                 заповнює зміст номерами сторінок
│   └── check_requirements.py       звірка з чеклістом методички (22 пункти)
├── data/
│   ├── raw/                        сирі дані без змін і скрипти збору
│   │   ├── fetch_binance_klines.py
│   │   ├── fetch_coingecko_markets.py
│   │   ├── fetch_coingecko_categories.py
│   │   ├── build_weekly_panel.py   побудова щотижневої панелі
│   │   └── binance_klines/         сирі відповіді API
│   ├── build_audit_weekly.csv      що вилучено під час побудови панелі
│   ├── join_audit_weekly.csv       зіставлення символів Binance і CoinGecko
│   ├── price_breaks_weekly.csv     паузи в торгах
│   ├── structurally_cleaned/       після структурного очищення (розділ 2)
│   └── analytical/                 фінальний аналітичний датасет (розділ 4)
├── legacy/monthly/                 перша, місячна версія панелі

```

## Відтворення

```

python3 tools/docx/build.py                # текст роботи
python3 tools/docx/toc.py                  # зміст (потрібен LibreOffice)

```

## Каталог bonus

Містить історію пошуку моделі на попередній, місячній панелі: підбір
гіперпараметрів, покрокову валідацію, порівняння цільових змінних і
симуляцію портфелів. Розбір у `bonus/bonus_report.md`. До оцінювання
курсової ці матеріали не належать, але саме там знайдено рішення про
крос-секційну ціль, яке покладено в основу роботи.

## Обмеження

Вибірка містить лише монети, що торгуються станом на момент збору даних,
тому зміщення виживання не усунене. Дані взято з однієї біржі. Модель
оцінює відносний результат монети й не прогнозує напрям ринку загалом.
